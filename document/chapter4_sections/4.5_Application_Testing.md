# 4.5 Application Testing

Beyond the machine learning model evaluation, the IKMS web application was subjected to a comprehensive testing regime to validate the correctness, stability, and integration of its components. Testing was conducted across three levels: unit tests, system tests, and integration tests.

## 4.5.1 Unit Tests

Unit testing was performed on individual backend functions and API endpoints in isolation, using Python's built-in `unittest` framework. Each test verified that a single function or route produces the correct output for a given input, independent of other system components.

Key unit tests included:

| Test Case | Component Tested | Expected Result | Status |
|---|---|---|---|
| Test user registration with valid data | `POST /register` API | Returns 201, user record created | ✅ PASS |
| Test login with correct credentials | `POST /login` API | Returns 200 with JWT token | ✅ PASS |
| Test login with incorrect password | `POST /login` API | Returns 401 Unauthorized | ✅ PASS |
| Test document upload with valid PDF | `POST /documents/upload` | Returns 201, document stored | ✅ PASS |
| Test document upload without auth token | `POST /documents/upload` | Returns 401 Unauthorized | ✅ PASS |
| Test search returns results for valid query | `GET /search?q=malaria` | Returns JSON array of documents | ✅ PASS |
| Test search returns empty for no-match query | `GET /search?q=xyzabc123` | Returns empty array, 200 OK | ✅ PASS |
| Test admin stats endpoint (sys_admin role) | `GET /admin/stats` | Returns JSON statistics object | ✅ PASS |
| Test admin stats endpoint (researcher role) | `GET /admin/stats` | Returns 403 Forbidden | ✅ PASS |
| Test TF-IDF keyword extraction function | `extract_keywords(text)` | Returns list of ≥5 keywords | ✅ PASS |
| Test LDA topic assignment function | `get_document_topic(text)` | Returns integer topic ID 0–9 | ✅ PASS |
| Test recommendation function | `get_recommendations(doc_id)` | Returns list of 5 document IDs | ✅ PASS |

*Table 4.9: Unit Test Results*

All 12 critical unit tests passed successfully. The authentication boundary tests (unauthorized access attempts returning 401 and role-based access returning 403) are particularly important for system security and were prioritized in the testing plan.

## 4.5.2 System Tests

System testing evaluated the complete end-to-end behavior of the application from the user's perspective, simulating realistic usage scenarios across the full stack (frontend → backend API → database → Elasticsearch).

The following key user flows were tested:

### Test Scenario 1: New User Registration and Login
- A new user navigated to the registration page and created an account with a valid name, email, and password.
- Upon submission, the system created the user record in the database and redirected to the login page.
- The user logged in successfully and was redirected to the Researcher Dashboard.
- **Result:** ✅ PASS — Full flow completed in under 3 seconds.

### Test Scenario 2: Document Discovery via Search
- A logged-in user navigated to the search page and entered the query "malaria treatment Ethiopia."
- The system returned a ranked list of relevant documents, with titles and abstracts displayed on result cards.
- The user applied a filter for a specific institution and the results narrowed correctly.
- **Result:** ✅ PASS — Search results returned in an average of 780ms via Elasticsearch.

### Test Scenario 3: Research Document Upload and Moderation
- A verified researcher uploaded a new PDF document, entering the title and abstract.
- The system extracted text, generated TF-IDF keywords, assigned an LDA topic, and stored the document with a "Pending" status.
- The document appeared in the System Admin's Review Queue.
- The admin approved the document; it subsequently appeared in public search results.
- **Result:** ✅ PASS — The full upload-to-publish pipeline completed successfully.

### Test Scenario 4: Independent Publisher Verification Request
- An unverified researcher selected "Independent Researcher" from the verification modal.
- The system saved an affiliation request (with no institution_id) to the database.
- The request appeared in the Master Admin Dashboard under "Independent Publishing Requests."
- The admin approved the request; the user's `is_verified` field was updated to `True` in the database.
- The researcher received an in-app notification confirming their approval.
- **Result:** ✅ PASS — End-to-end verification flow completed correctly.

### Test Scenario 5: Content-Based Recommendation
- A user opened the detail page for a document on "maternal nutrition in Ethiopia."
- The system displayed 5 recommended papers, all of which were related to maternal health or nutrition topics.
- **Result:** ✅ PASS — 4 out of 5 recommended papers were judged highly relevant by the test evaluator.

Integration tests verified that the different layers and components of the system communicate and exchange data correctly.

| Integration Point | Test Description | Result |
|---|---|---|
| Frontend ↔ Backend API | React frontend correctly sends HTTP requests and renders API responses | ✅ PASS |
| Backend ↔ Supabase PostgreSQL | All CRUD operations (Create, Read, Update, Delete) on users, documents, institutions execute correctly | ✅ PASS |
| Backend ↔ Supabase Storage | PDF files upload to and are retrieved from Supabase Storage bucket correctly | ✅ PASS |
| Backend ↔ Elasticsearch | Documents are indexed in Elasticsearch upon upload and retrieved correctly via search queries | ✅ PASS |
| JWT Auth Middleware ↔ Protected Routes | Auth decorator correctly validates tokens and blocks unauthorized access to all protected endpoints | ✅ PASS |
| ML Pipeline ↔ Database | TF-IDF keywords and LDA topic scores are correctly persisted to the `topic_scores` table after processing | ✅ PASS |
| Notification System ↔ Admin Actions | Approval/rejection of independent publisher requests correctly creates user notification records | ✅ PASS |

*Table 4.10: Integration Test Results*

All integration points functioned correctly, confirming that the individual system components work cohesively as a unified platform.

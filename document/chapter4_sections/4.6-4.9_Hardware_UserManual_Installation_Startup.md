# 4.7 User Manual Preparation

A user manual was prepared to guide end-users through the key features and workflows of the IKMS platform. The manual covers five primary user roles: Public Visitor, Researcher, Institution Admin, System Moderator, and System Admin.

## Public User Guide

1. **Accessing the Platform:** Open a web browser and navigate to the IKMS URL. The homepage displays the search interface and featured research documents — no login is required for basic discovery.
2. **Searching for Research:** Type a keyword (e.g., "tuberculosis," "maternal mortality") into the main search bar and press Enter. Results appear ranked by relevance.
3. **Filtering Results:** Click "Advanced Filters" below the search bar to filter results by institution, publication year, or topic.
4. **Downloading a Document:** Click a document card to view its detail page, then click the "Download PDF" button to access the full document.

## Researcher User Guide

1. **Creating an Account:** Click "Register" and fill in your name, email, and password. A new account is created with the "Researcher" role by default.
2. **Requesting Publishing Access:** From your Researcher Dashboard, click "Request Publishing Access" and select either your institution or "Independent Researcher." Submit the form to notify an administrator.
3. **Uploading a Document:** Once verified, navigate to "Upload New" in your dashboard, attach your PDF, fill in the title and abstract, and click "Submit for Review."
4. **Tracking Documents:** The "My Uploads" tab shows the moderation status (Pending / Approved / Rejected) of all your submitted papers.
5. **Notifications:** Click the bell icon (🔔) in the top-right header to view system notifications, including publishing request approvals.

## System Admin Guide

1. **Accessing the Admin Portal:** Log in with a System Admin account to be redirected to the Master Admin Dashboard.
2. **Review Queue:** Navigate to "Review Queue" to see all pending documents. Click a document to expand its details, then select "Approve," "Request Revision," or "Reject."
3. **User Directory:** Navigate to "User Directory" to view all registered users, reassign roles, and review Independent Publishing verification requests.
4. **Institutions:** Navigate to "Institutions" to add, edit, or remove institutions from the platform registry.
5. **Audit Log:** Navigate to "Audit Log" to review a complete history of all moderation actions taken on the platform.

# 4.8 Installation Process

This section provides step-by-step instructions for installing and running the IKMS application in a local development environment.

## Prerequisites

Before installation, ensure the following are installed on your machine:
- Python 3.10 or higher (`python --version` to check)
- Node.js 18 LTS (`node --version` to check)
- Git (`git --version` to check)

## Step 1: Clone the Repository

```bash
git clone https://github.com/your-username/ikms-project.git
cd ikms-project
```

## Step 2: Configure Environment Variables

Navigate to the `backend/` directory and create a `.env` file based on the provided `.env.example`:

```bash
cd backend
copy .env.example .env   # Windows
```

Open the `.env` file and fill in your Supabase project credentials:

```
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=your-supabase-anon-or-service-key
JWT_SECRET_KEY=your-random-secret-string
```

## Step 3: Set Up the Backend

```bash
# Inside the /backend directory
pip install -r requirements.txt
python sync_tables_minimal.py   # Initialize local SQLite database tables
python app.py                    # Start the Flask development server
```

The backend will start on `http://localhost:5000`.

## Step 4: Set Up the Frontend

Open a new terminal window:

```bash
cd frontend
npm install          # Install all Node.js dependencies
npm run dev          # Start the Vite development server
```

The frontend will start on `http://localhost:5173`.

## Step 5: Access the Application

Open a web browser and navigate to `http://localhost:5173`. The IKMS application home page will load.

> **Note:** An active internet connection is required for Supabase Cloud operations (authentication, document storage). The local SQLite database is used as a secondary store for ML metadata, notifications, and moderation logs.

# 4.9 Start-Up Strategy

The start-up strategy defines the approach for deploying and launching the IKMS system from a development prototype to a live, operational service within a research institution.

## Phase 1: Pilot Deployment (Month 1–2)

The system will initially be deployed in a **controlled pilot environment** involving a single partner institution. A small group of 10–20 selected researchers will be onboarded to use the platform, providing early feedback on usability, search quality, and document submission workflows. The System Admin will manually review all document submissions during this phase.

Objectives:
- Validate the end-to-end document lifecycle (upload → moderation → publish → discovery).
- Identify usability issues through direct user observation.
- Stress-test the Elasticsearch indexing pipeline with real institutional documents.

## Phase 2: Multi-Institutional Onboarding (Month 3–4)

Following pilot validation, additional institutions will be onboarded. Each institution will be assigned an Institution Admin account to manage their members and moderate their own document submissions. The system's multi-tenant architecture was designed to support this expansion without requiring code changes.

Objectives:
- Populate the platform with a critical mass of real research documents.
- Enable cross-institutional search for the first time.
- Train Institution Admins on the dashboard and moderation workflows using the prepared user manual.

## Phase 3: Public Launch and Maintenance (Month 5+)

The platform will be fully opened to public access (read-only for unregistered visitors) and widely promoted within the Ethiopian academic research community.

Post-launch maintenance plan:
- **Monitoring:** Server uptime, API response times, and error logs will be monitored via the Supabase dashboard and Flask logging.
- **Model Retraining:** The LDA and TF-IDF models will be periodically retrained as the document corpus grows (recommended after every 1,000 new document uploads) to ensure topics remain relevant and keywords accurate.
- **Security Updates:** Python and Node.js dependencies will be regularly updated to patch any security vulnerabilities.
- **Feature Enhancements:** User feedback collected during the pilot will be prioritized to guide future feature development (e.g., Amharic language support, advanced analytics dashboards).
